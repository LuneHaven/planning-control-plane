# 示例项目（PCP 中文示例目标仓库）

本目录是 Planning Control Plane 的一个**合成目标仓库**，用来展示 PCP 可以
运行在任意仓库之上，不依赖任何特定产品、领域或业务数据。全部内容都是通用
占位素材。

与 [`../demo-project`](../demo-project)（英文示例）的关系：两者是**各自独立
的规划数据**，描述的是同一类通用软件项目规划场景。PCP 的语言切换只切换界面
语言，不会翻译规划内容本身——所以中文界面的完整效果需要中文规划数据来展示，
这就是本目录存在的原因。

## 目录内容

- `.planning/` —— 规划图：
  - `project.yaml` —— 项目配置、当前焦点（`P2-A4`）、权威根目录、`ui.locale: zh-CN`
  - `roadmap.yaml` —— 留空；节点存放在 `nodes/`（两个来源会合并）
  - `nodes/` —— 每个规划节点一个 YAML 文件（`P1` → `P2` → `P2-A` → `P2-A1..A4`）
- `docs/rollout/` —— 模拟的**规范文档**（占位）
- `docs/notes/` —— 模拟的**现状/佐证**记录

规划树：

```
P1  规划基础
└─ P2  产品推广
   └─ P2-A  推广策略
      ├─ P2-A1  调研现有推广文档
      ├─ P2-A2  定义推广就绪标准
      ├─ P2-A3  冻结推广顺序
      └─ P2-A4  推广就绪度预检   ← 当前焦点
```

本示例覆盖：多层级的冻结决策（子节点继承）、一条阻塞决策（`P2-A4` 上的
`BD-401`）、依赖关系（`P2-A4` 依赖 `P2-A3`，`P2-A3` 阻塞 `P2-A4`）、可真实
解析的规范链接与佐证链接，以及一个当前焦点。

## 试一试

在本目录下（`pcp` 已从仓库根目录安装）：

```bash
pcp status          # 概览：焦点、进度、阻塞
pcp context         # 当前焦点的会话恢复 capsule
pcp context --full  # 追加祖先、相关节点、依赖细节
pcp validate        # 结构 + 一致性校验
pcp build           # 重新生成 .planning/dist（一次性投影）
pcp build --check   # 校验 dist 与一次全新确定性构建是否一致
```

然后直接打开 `.planning/dist/index.html`（双击即可，完全离线）。顶栏有
`English / 中文` 切换：切换是即时的，只保存在浏览器里，永远不会修改规划
数据或 `project.yaml`。切到 English 时界面变成英文，而节点标题、目标、
决策摘要等规划内容仍然是中文原文——这是预期行为。
